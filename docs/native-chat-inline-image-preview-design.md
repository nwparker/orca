# Native chat inline image preview

Status: implemented and independently reviewed. Focused behavior tests and hidden Electron visual validation pass.

## Decision

An ordinary click, tap, or keyboard activation on an image displayed in native chat opens the existing pan-and-zoom image dialog immediately. This includes Markdown images in paragraphs, lists, blockquotes, and GFM table cells. The image itself is the preview affordance; choosing a file destination becomes a secondary action inside the dialog.

Text links, linked file paths, document chips, terminal links, and the user's link-click setting keep their existing behavior. A text link such as `[screenshot](image.png)` remains a link. The new behavior applies to rendered images, rather than every destination with an image extension. Composer and transcript attachment thumbnails already open the correct dialog and retain that behavior.

## Interaction contract

| Gesture or state                                                                       | Result                                                                                                                                                                                                                                                                           |
| -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Primary click / tap on displayed image                                                 | Open the dialog synchronously. Prevent enclosing chat rows or linked-image wrappers from navigating. No file-actions popup appears first.                                                                                                                                        |
| Enter or Space on focused image trigger                                                | Open the same dialog. Prevent Space from scrolling the transcript.                                                                                                                                                                                                               |
| Platform direct-open modifier on an image that previously routed through `onLinkClick` | Preserve existing direct-open behavior through that callback: Cmd on macOS, Ctrl on Windows/Linux. Shift keeps the current system-default routing. Reuse platform gesture helpers.                                                                                               |
| Other modified clicks                                                                  | Delegate to the prior link handler where the source was already link-routed; do not invent another shortcut or coerce them into preview.                                                                                                                                         |
| Middle click / right click                                                             | Preserve existing auxiliary-link and context-menu behavior; they do not open the image dialog. Native-chat Copy image remains available where supported.                                                                                                                         |
| Link-click setting is `actions`, `open`, or `none`                                     | The image's ordinary activation opens preview in every case. The setting still governs links.                                                                                                                                                                                    |
| Image source is missing                                                                | Render the existing alt/placeholder text; do not create an empty interactive control.                                                                                                                                                                                            |
| Source read or image decoding is pending                                               | The dialog is already open with a usable Close control. Retain the existing viewer's fallback until the source is ready; the shared source hook currently represents both pending and unavailable sources as undefined. A separate delayed-loading state is outside this change. |
| Image unavailable, permission denied, offline, or invalid image data                   | Keep the dialog open with localized “Preview unavailable” feedback. Do not silently open a different app or fall back to another host. Offer eligible file actions.                                                                                                              |

Use `View image: <alt or filename>` as the trigger's accessible name, and use the alt text, filename, or localized “Image” as the dialog title. Do not add duplicate labels or a visible instruction under each thumbnail. Existing thumbnail sizing, table sizing, scroll behavior, and source dimensions stay intact. A zoom cursor and existing focus-visible ring communicate the affordance.

Linked images require explicit coverage. Their ordinary activation previews the image source, matching the current image handler's source choice. Preserve the enclosing link's existing auxiliary/modifier handling where applicable. Render a single interactive trigger: avoid a button nested inside an anchor. An image-only anchor renderer can provide the preview trigger for its image, while ordinary anchors continue through the existing renderer. A click must produce only one outcome.

## Secondary actions inside the dialog

Add a quiet **File actions** ghost control to the image dialog toolbar for a resolved file source. Use the existing shadcn `DropdownMenu` with `modal={false}`, following existing menus inside dialogs. The preview remains the modal owner; a second modal menu must not block its Close control. Retain standard menu keyboard navigation and focus behavior. Keep Close at the end of the toolbar. The control may have a visible text label; an icon-only form requires the existing Tooltip primitive and an accessible name.

Build its rows from `nativeChatFileLinkActions` / `nativeChatLinkActions` for the original source and chat owner. File-menu eligibility requires a resolved image runtime owner as well as a file-link context; a non-null link context alone does not prove a remote image owner is available. Re-evaluate eligibility on owner changes, and do not retain runnable stale-owner rows. Preserve eligible Open file, Open in this group, Open with default app or Download & open with default app, and Reveal actions. Never use a renderer's `blob:` URL as the file destination. For an HTTP(S) image, the corresponding optional control is **Link actions** and uses existing web destinations. Data/blob-only images have no file menu. No new settings row is needed.

Opening or dismissing the dropdown leaves the image dialog open. Escape dismisses the menu first, then dismisses the dialog on the next press; a click on Close closes the dialog immediately even with a menu open. Selecting an action closes the menu and preview, then invokes the existing action once after the close has committed, so a newly opened editor is visible. Suppress menu focus restoration when handing off to an action or closing the preview; it must not focus an unmounted toolbar or pull focus back from the destination. A normal menu dismissal restores focus to its trigger. Closing the dialog restores focus to the original image when still mounted, using the viewer's existing active-modal guard. Action failure keeps its current toast/error contract. Keep menu content within the viewer's React subtree so Radix nested-layer handling applies; test the portaled menu rather than broadly disabling outside dismissal or the dialog focus trap.

The slot in `PanZoomImageDialog` accepts content only; the generic viewer should not import chat stores, file ownership, or action builders. Existing image previews outside chat continue to render their current toolbar.

## Rendering and ownership design

Use the existing `CommentMarkdownExtension.components` boundary for the document variant used by transcript prose. Compact cards retain their existing trust and rendering behavior in this change. `NativeChatMarkdown` composes a stable native-chat `img` renderer with `useNativeChatVisualMarkdownExtension`, preserving its remark plugins, sanitize attributes, and `div` renderer. There is no need to add a second shared `renderImage` API or change ordinary shared document defaults. Leave normal anchor rendering and `onLinkClick` intact; only add a narrowly scoped linked-image adaptation if needed to avoid nested interactive elements. The custom image renderer must preserve missing-source handling and GitHub/Jira special attachment adapters rather than bypassing those existing branches. It must not override the compact variant's image trust checks.

The native-chat renderer adapts sources and action callbacks into the extended `ExpandableMarkdownImage`, reusing document image styling and the one `PanZoomImageDialog`. Add a small tab-aware provider at `NativeChatView` for structured and bridged chats, using existing runtime and file-link context hooks once per surface. Expose the contexts and visibility/session identity to descendants; do not resolve ownership independently for every image or thread fields through prose/tool components. Prefer already-resolved contexts where the chosen boundary provides them. Keep the extension object and image component type stable while unrelated chat state or streamed text changes.

Source handling follows existing preview contracts:

1. HTTP(S), trusted data, and blob sources retain their current URL handling and sanitation. Do not broaden the URL protocol allowlist, arbitrary remote fetching in compact cards, or private-attachment authentication handling. Existing GitHub/Jira attachment adapters continue to own their special sources.
2. Relative, absolute, and allowed file-URI sources resolve against the chat's own directory using existing path/URI resolvers. Preserve Windows drive paths, escaped spaces, and separators. Reuse `resolveNativeChatFileLink` where its literal-path behavior fits; do not treat an image filename suffix as a source-code line locator.
3. Read a resolved file through `useLocalImageSrc` with the existing owner runtime context and `chatImageAccess()`. The latter preserves real image-type checks and local share restrictions; an agent-authored path is not a user-named arbitrary file grant.
4. Explicitly distinguish unresolved owner (`null`, no read) from legacy local context (`undefined`). A paired/SSH source must never fall back to the client's filesystem while ownership is loading or disconnected.
5. Let `useLocalImageSrc` own its existing cache lease and stale-read cancellation. Reuse `observeTranscriptVisibility` only if the new file thumbnails need the same read gating as transcript attachments; then keep the existing `near || open` lease rule. Do not introduce a second cache, resource manager, or custom lease subsystem. Async results for a previous owner/source cannot replace the current preview.

Keep the image component identity stable during streaming so appending unrelated prose does not reset its dialog. Start with component-local preview state, matching `ExpandableMarkdownImage` and existing transcript attachment previews. Conversation replacement or chat deactivation must not leave a stale portal visible; use the existing conversation/visibility boundary. Ordinary virtualized row unmount may close its preview, matching existing attachment behavior. Persisting a viewer across row eviction is outside this bug fix; do not add a transcript preview manager or global store.

## Local, remote, mobile, and workspace parity

- **Desktop platforms:** reuse path utilities, modifier helpers, and action builders for macOS/Linux/Windows. No new process, shell, native module, or IPC channel is required. Test both theme modes and large chat text settings.
- **Paired and SSH:** all file bytes and open actions retain their owner route and SSH generation expectations. Keep the dialog responsive while reads are delayed. Old servers continue using existing file-preview APIs; unsupported or failed reads show the existing unavailable state. This design adds no required wire field, migration, or coordinated client/server upgrade.
- **Folder and floating workspaces:** use existing native-chat directory/owner resolution, which already includes folder workspace records and local floating workspaces. No git-root, branch, or repository prerequisite is introduced. A chat launched in a subdirectory resolves relative images against that chat's directory.
- **Web renderer:** use the same image preview path and existing capability-dependent actions. Keep the existing policy that web clients do not offer the desktop Copy image operation. Do not invoke client-local filesystem APIs as a remote fallback.
- **Native mobile:** it uses `MobileMarkdown`, not `CommentMarkdown`. `MobileNativeChatProse` attachment presses already call `MobileNativeChatRowOverlaysContext.openImage`, which presents `MobileNativeChatImageViewer`. Those displayed thumbnails already have the requested preview behavior. Inline Markdown currently lacks that `renderImage` wiring and generally remains text links rather than displayed thumbnails. Keep this implementation focused on desktop/web rendered inline images; native-mobile inline-image rendering is a separate parity consideration. A future small extension can use `MobileMarkdown.renderImage` and the same attachment pressable/viewer, including table cells, while preserving long press. Keep unavailable host paths as placeholders and do not introduce a mobile host-file transport here.
